Understanding IDOR

Insecure Direct Object Reference — OWASP Top 10

What is IDOR?

IDOR happens when an application uses a user-controlled input to access objects directly without verifying that the user is authorized to access them. The most common example is an ID in a URL — like /orders/4. If the server doesn't check whether order 4 belongs to you, anyone can access it just by changing the number.

Authentication vs Authorization

These two are constantly confused — even by developers.

  • Authentication — proves who you are. Logging in with a username and password is authentication.
  • Authorization — controls what you're allowed to do. Checking that an order belongs to you before showing it is authorization.

IDOR is always an authorization failure — the app knows who you are, it just never checks what you're allowed to see.

The Three Difficulty Levels

Low — Plain Integer IDs

Orders are accessed by sequential integers like /orders/1, /orders/2. No ownership check exists. An attacker just increments the number to access anyone's data.

// Vulnerable code
const order = db.prepare('SELECT * FROM orders WHERE id = ?').get(id);
// No check — returns the order to anyone who asks

Medium — Base64 Encoded IDs

IDs are Base64 encoded, so 1 becomes MQ==. Looks confusing, but Base64 is not encryption — anyone can decode it in seconds using atob() in the browser console.

// Still vulnerable — just obscured
atob('MQ==') // → '1'
atob('NA==') // → '4'
// The ID is still sequential underneath

High — UUIDs + Ownership Check

Orders use unpredictable UUIDs like a3f8c21d-... AND the server verifies ownership before returning any data. Both layers are needed.

// Secure code
const order = db.prepare('SELECT * FROM orders WHERE uuid = ?').get(uuid);
if (order.user_id !== req.session.user_id) {
  return res.status(403).json({ error: 'Forbidden' });
}

How to Test It Yourself

  1. Login as alice (password: alice123)
  2. Go to your dashboard and click any order
  3. In the URL, change the ID to 4, 5, or 6 — those belong to Bob
  4. On Low difficulty, you'll see Bob's orders with no error
  5. Switch to High difficulty and try the same — you'll be blocked
